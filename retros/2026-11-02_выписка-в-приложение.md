# Итог сессии: загрузка банковской выписки в «Склад ВЛ»

**Дата:** 2026-11-02

1. **Задача:** выписка Точки/Альфы кнопкой → оплаты сопоставляются с грузами → после подтверждения в грузе «Клиент оплатил» и
   «Дата полной оплаты» (от них зп). Повтор не задваивает. План `plans/2026-11-02_выписка-в-приложение.md`, владелец: «Да, делай».
2. **Что сделали:**
   - `app-sklad/vypiska.py` — разбор формата 1С (Точка и Альфа одинаковые, `1CClientBankExchange`, cp1251), только поступления,
     переводы между своими (ИНН ВЛ 3812166710, «Шерстов», наши р/с) пропускаются; сравнение названий — из `tools/sverka_oplat/match.py`.
     Сопоставление: клиент (ИНН из справочника или название) + сумма = долг, или номер счёта в назначении; один платёж за 2–4 груза
     клиента (подбор суммы); оплата частями → «проверь»; платёж не раньше 10 дней до создания груза.
   - `server.py`: таблицы `platezh` (отпечаток счёт|№|дата|сумма|ИНН — UNIQUE) и `oplata` (платёж ↔ груз ↔ сумма), поля груза
     `schet` («Счёт клиенту №») и `paid_manual` (введено руками до выписки); действия vypiska_load, oplaty_list, oplata_link,
     oplata_unlink, platezh_ignore. «Клиент оплатил» = руками + платежи; дата — платежа, которым набралась ставка.
   - `static/app.js`: вкладка «Оплаты» (кнопка/перетаскивание, списки «Уверенно» / «Проверь» / «Не нашли груз» / скрытые),
     в карточке груза — платежи с «отвязать», поле оплаты только для чтения при наличии платежей.
3. **Результат:** решено — проверено на копии базы (порт 8799, тестовая сессия): 5 счетов, 439 поступлений; повторная загрузка —
   новых 0 (и через HTTP); не-выписка — понятная ошибка; точное совпадение и «1 платёж за 2 груза» — «уверенно» и проводятся;
   оплата частями: 1-я часть — сумма без даты, 2-я сама стала «уверенно» → оплачено, зп «начислено за 10.2026»; отвязка
   пересчитывает; ручная сумма + «прибавить» работает; перерасход платежа запрещён. Вкладки «Заявки»/«Зарплата» открываются.
   Грузы примера С534 (июль) сами нашли свои настоящие оплаты в выписке. Рабочая `sklad.db` не тронута (таблицы добавятся при запуске).
4. **Что пошло не так и почему:** сначала автоскрывал всех плательщиков со словом «БАНК» — под это попали 2 настоящие оплаты
   клиентов (в названии фирмы «…БАНК…»). Сделал правило по назначению (проценты, кэшбэк, комиссия, внесение, «возврат…»).
   Длинный heredoc с Python в Bash один раз не разобрался — патчи писал отдельным файлом в scratchpad.
5. **Правила на будущее:** не прятать платежи по одному слову в названии плательщика — смотреть назначение. Проверка выписки —
   на копии базы, payer/назначения в чат не выводить.
6. **Следующий шаг:** владельцу перезапустить приложение (закрыть окно «Склад ВЛ» и открыть ярлык) — появится вкладка «Оплаты»;
   загрузить свежую выписку. Дальше по очереди: справочники из архива, затем сервер для 9–10 человек. Код не закоммичен — спросить.
