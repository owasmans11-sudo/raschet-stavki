# Стартовый набор проекта

## Что внутри

| Файл/папка | Роль |
|---|---|
| `CLAUDE.md` | Правила работы + триггер: при `completed: false` агент ведёт онбординг |
| `ONBOARDING.md` | Сценарий онбординга на 60–90 минут из 7 шагов (ведёт агент) |
| `context/` | `PROJECT.md` (контекст), `words.md` (слова клиента дословно) |
| `plans/` | Планы функций, шаблон `_TEMPLATE.md` |
| `retros/` | Итоги сессий, шаблон `_TEMPLATE.md` |
| `rules/` | Маршрутизатор правил и регламент безопасности |
| `prompts/` | Девять готовых промптов и `INDEX.md` |
| `.gitignore` | Исключает `.env`, ключи, логи |

## Как выдать клиенту

1. Пройти `methodology/handover.md` (чек-лист передачи).
2. Скопировать **содержимое** этой папки в корень проекта клиента. Если у него уже есть `CLAUDE.md`, не перезаписывать: встроить блок «СТОП» и разделы вручную, а `.gitignore` — слить.
3. Клиент открывает проект в Claude Code (или Codex, сославшись на `CLAUDE.md`) и пишет любое «привет».
4. Агент видит `completed: false` и ведёт онбординг. Первая сессия — с вами рядом.
5. Записать передачу в `clients/<клиент>/delivered.md`.

## Что можно настроить под клиента

- Добавить в `rules/INDEX.md` свои строки (тексты, дизайн, юридическое).
- Убрать лишние промпты из `prompts/`, если клиенту не нужны.
- Для Codex продублировать содержимое `CLAUDE.md` в `AGENTS.md`.

## Ограничения

- Заготовка не проверена на реальном клиенте: первый онбординг проведите сами и запишите, что поправить.
- Агент в онбординге ничего не ставит без «да», но команды установки всё равно проверяйте глазами.
- Если клиент не использует Git, шаг 4 онбординга предложит завести его; не настаивайте, если не хочет.
