# План: приложение «Экспедирование через склад»

**Дата:** 2026-11-02  **Размер:** L  **Статус:** фаза 1 готова (2026-11-02)

## Что хотим получить
Своё приложение (вместо работы в «Умной логистике»), удобное для экспедирования через склад:
груз клиента ведётся одной карточкой по всей цепочке «забор → склад → фура → склад → развоз».
Задолженность пока не делаем.

## Основа
Python + SQLite (база — один файл в папке проекта), окно — в браузере (Chrome). Один компьютер.
Позже можно перенести на сервер (PostgreSQL), чтобы работали все сотрудники.

## Склады (слова владельца, 2026-11-02)
Щёлково, Красноярск, Иркутск, Улан-Удэ, Чита (Улан-Удэ и Чита — два разных склада). Список складов редактируется в настройках.

## Вкладки
1. **Заявки (грузы)** — заказчик, груз, кг, м³, места, откуда, куда, ставка клиента, компания (ВЛ / ИП / МВЛ),
   форма оплаты. Внутри — отрезки: «до склада», «межгород (фура)», «развоз»; у каждого перевозчик, водитель, ставка.
   Статус: ждёт забора → на складе → в фуре → прибыл → доставлен.
2. **Склад** — выбор склада, что на нём лежит (груз, клиент, кг, м³, места, сколько дней). Кнопки «Принять», «Отгрузить».
3. **Фуры** — создать фуру (номер ТС, водитель, маршрут, склад погрузки, склад приёмки, ставка, вместимость),
   галочками добавить грузы со склада; видно набранные кг/м³ и остаток места; у каждого груза — точка выгрузки.
   Расходы фуры делятся по кг → прибыль по каждой заявке (как в плане зарплаты с прибыли по фуре).

Фуры бывают 82 м³ и 110 м³ (слова владельца) — выбор при создании фуры. Грузоподъёмность по умолчанию 20 т
(допущение, меняется у каждой фуры).

## Критерии приёмки
- [ ] Завёл груз → он в статусе «ждёт забора»; принял на складе Иркутск → виден во вкладке «Склад» Иркутска.
- [ ] Создал фуру 82 м³ Иркутск → Улан-Удэ → Чита, добавил 3 груза → видны сумма кг/м³ и остаток места; грузы ушли со склада.
- [ ] Расходы фуры поделены по кг; сумма долей = расходам фуры; прибыль по заявке считается.
- [ ] В карточке груза видна вся цепочка с адресами и перевозчиками каждого отрезка.
- [ ] Для примера загружена фура С534НХ03 из `C:\РАБОТА\Цепочка фуры С534НХ03 (сложная №2).xlsx`.

### Фаза 1б: перегруз и деление груза (владелец: «продолжай», 2026-11-02)
- **Перегруз:** груз может ехать несколькими фурами подряд (Щёлково → Красноярск одной, Красноярск → Чита другой).
  Новая таблица «рейсы» (груз — фура — где выгрузить). Если выгрузили не на складе назначения — груз снова «на складе»
  и его можно погрузить в следующую фуру. Доля расходов считается по каждой фуре, где груз ехал.
- **Деление:** на складе кнопка «Разделить»: указываешь кг / м³ / места отделяемой части → новая заявка «Г-0011-2».
  Ставка клиента и ставки забора/развоза делятся пропорционально весу (если веса нет — объёму, потом местам), сумма не меняется.
- Существующая база переводится автоматически.
- Как проверим: груз Щёлково → (фура 1) Красноярск → (фура 2) Чита; деление 10 мест на 6 + 4 с разными фурами;
  суммы ставок до и после деления совпадают.

### Фаза 2а: печать заявок ВЛ (владелец выбрал, 2026-11-02)
- Кнопки печати: в карточке груза — «Заявка с клиентом», «Перевозчику: забор», «Перевозчику: развоз»; в фуре — «Заявка на фуру».
- Документ — Word (.docx) в утверждённом стиле «вариант 3» (`tools/vl_style.py`). Юридический текст и наши реквизиты берутся
  слово в слово из готовых шаблонов «новый дизайн» в корне проекта — шаблоны не меняются.
  Шаблон по компании груза: забор — «до склада ВЛ»; развоз — «со склада ВЛ» / «со склада ИПШ»; фура — «межгород фура ВЛ»;
  клиент — «с клиентом ВЛ (вариант 3)» / «с клиентом по МВЛ». Нет шаблона (например, забор от ИП) — сообщение, а не подмена.
- Заполняется то, что есть в приложении (номер, даты, адреса, груз, ставка, перевозчик, водитель); остальное — пустые поля, как в бланке.
- Файлы — в папку `Заявки из приложения/` в проекте (не в git), сразу открываются в Word.
- Как проверим: печатаю 4 вида по примеру С534НХ03, открываю в Word → PDF, смотрю глазами; сверка условий со шаблоном — 0 расхождений.
