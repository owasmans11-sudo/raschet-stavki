# Итог сессии: клиент / перевозчик из файлов

**Дата:** 2026-11-02

1. **Задача:** «для клиентов тоже самое… чтобы данные брались или с заявки или с карточки предприятия».
2. **Что сделали:** `app-sklad/firma.py` — реквизиты компании: ИНН (только с верной контрольной суммой) как якорь, поля
   (КПП, ОГРН, адреса, р/с, банк, БИК, к/с, руководитель, основание, телефон, почта, название) — к ближайшему ИНН;
   наши ИНН (ВЛ 3812166710, ИП 381100987938, МВЛ 3812162635) отбрасываются; несколько компаний — выбор.
   Проверки: ОГРН/ОГРНИП, р/с + БИК, к/с + БИК — контрольные ключи. Две колонки реквизитов: OCR теперь помечает правую
   половину листа табуляцией (`raspoznat._lines`), колонки разбираются отдельно. «О0О» → ООО.
   Справочник «Контрагенты» (вкладка), окно «из файлов» (общая зона перетаскивания/Ctrl+V с водителями — bindDrop),
   в грузе — «Заказчик», в отрезках — «Перевозчик» с подсказкой и кнопкой «из файлов»; печать — раздел 1 и блок «16. Заказчик»
   в заявке с клиентом, блок «11. Перевозчик» в заявке перевозчику. Файлы — `app-sklad/files/firma/<id>/`.
3. **Результат:** решено (фаза 1) — проверено в браузере на вымышленных документах (карточка 13 полей; заявка в 2 колонки —
   клиент 10 полей, наши пропущены; выбор из 2 компаний; печать). Архив — только счётчики (см. план). Регрессия водителей — без изменений.
   Тестовые записи и файлы удалены точечно; записи владельца (водитель, Г-0012, Г-0013, файл во «входящих») не тронуты.
4. **Что пошло не так и почему:** склейка разбитых цифр сливала «ИНН КПП» в одно число — ИНН ищем без склейки;
   колонки «наши | клиента» OCR склеивает в строку — поля уходили к нашему ИНН; `rm` с маской заблокирован защитой — удалял по точным именам.
5. **Правила на будущее:** владелец уже пользуется приложением — тесты удалять только по своим id и точным именам файлов.
6. **Следующий шаг:** по желанию — фаза 2: из заявки клиента подставлять в груз адреса, даты, груз, вес, ставку.

## Продолжение: фаза 2 — груз из заявки клиента
- В карточке груза кнопка «📄 Заполнить из заявки клиента»: один файл → заказчик с реквизитами (firma.py) + № и дата заявки,
  адреса и даты погрузки/выгрузки, груз, вес, объём, места, ставка, НДС (`app-sklad/zayavka.py`; ставку, НДС, погрузку разбирает
  уже проверенный `tools/kart_fields.py`). Подставляется только в пустые поля груза и отрезков; № заявки клиента — в примечание.
- Проверено: вымышленная заявка → 11 полей груза + заказчик, наши реквизиты пропущены; в браузере вес 3000, введённый заранее,
  не перетёрт 2500 из заявки. 20 настоящих заявок (свежий OCR, только счётчики): № 19/20, ставка 18 (3 странные), адреса 16, даты 13–14,
  заказчик 11, груз — слабее (исправлен табличный вид «подпись / значение в следующей строке»); ~10 с на заявку (многостраничные сканы).
- Попутно исправлено в общих модулях: `kart_fields.find_date` принимал только 2025–2026 годы — с 2027 даты перестали бы находиться
  (теперь до текущего года + 1); `kart_fields.loading` срезал «д. 1» в конце адреса; `raspoznat.fix` — «180 о00» → «180 000».
  Это улучшит и ночную картотеку. Регрессия водителей — без изменений.
- В архиве (сплошной текст без строк) ставка почти не находится — проверять разбор заявок только на свежем OCR.
