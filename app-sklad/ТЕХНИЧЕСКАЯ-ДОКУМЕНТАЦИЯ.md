# Техническая документация Склад ВЛ

«Склад ВЛ» ведёт заявки на груз, движение через склады, назначение фур, контрагентов, водителей и платежи. Клонируйте весь репозиторий `raschet-stavki`. Папка `app-sklad` использует шаблоны из корня и модули из `tools`. Пошаговая настройка описана в [инструкции запуска](ЗАПУСК.md).

## Структура приложения

| Файл | Назначение |
|---|---|
| `server.py` | Сервер HTTP на стандартной библиотеке Python, статические ресурсы, API, SQLite, проверка входа и обновление схемы |
| `static/index.html`, `static/app.js`, `static/style.css` | Вкладки, формы, карточки и вычисления в браузере, включая расчёт прибыли и зарплаты |
| `static/login.html`, `vhod.py` | Вход, хеширование паролей, серверные сессии и файл первичного входа |
| `vypiska.py`, `excel.py` | Разбор банковской выписки, подбор оплат и экспорт Excel |
| `raspoznat.py`, `firma.py`, `zayavka.py` | Извлечение и разбор полей из входящих документов, карточек контрагентов и заявок |
| `pechat.py`, `../tools/vl_style.py` | Генерация и оформление договоров-заявок DOCX |
| `transport_docs.py`, `templates/` | Проекты ТН и экспедиторской расписки и фирменные бланки ООО/ИП |
| `backup.py` | Снимки базы и копирование вложений |

## API и поток данных

Сервер отдаёт интерфейс и JSON на одном адресе. `GET /api/state` загружает заявки, склады, справочники, фуры, рейсы, оплаты и историю. Изменения отправляются как JSON в `POST /api/<действие>`. Список обработчиков собран в `ACTIONS` в `server.py`. Основные операции — `gruz_save`, `gruz_accept`, `gruz_deliver`, `fura_save`, `fura_send`, `fura_unload`, `vypiska_load`, `print_doc`. После успешного действия интерфейс перечитывает состояние. Ошибки для пользователя передаются в JSON через `error`. Записи обработчика фиксируются при успехе, при ошибке выполняется откат транзакции.

Вход выдаёт cookie `sklad_s`. Вложения доступны через `/files/` после входа. `document_preview` возвращает заполняемые поля и список пропусков для выбранного участка, `print_doc` сохраняет DOCX, а `/documents/` отдаёт его как вложение после входа. Проекты ТН и расписки не подписываются и не отправляются в ГИС ЭПД.

## Схема данных

| Таблицы | Что хранят |
|---|---|
| `gruz`, `leg` | Карточки грузов и отдельные участки забора и развоза |
| `fura`, `reys` | Фуры и связи конкретных грузов с фурами и точками выгрузки. У груза могут быть несколько рейсов |
| `sklad`, `manager`, `voditel`, `kontragent` | Справочники складов, менеджеров, водителей и контрагентов |
| `log` | История движения груза |
| `platezh`, `oplata` | Строки выписок и распределение платежей по грузам |
| `auth`, `sessions` | Данные входа и сессии |

При запуске `init_db()` создаёт таблицы и добавляет недостающие поля через `NEW_COLS`. Перед изменением схемы проверьте запуск и с пустой базой, и с отдельной копией существующей. Скрипты `import_*.py`, `seed_*.py` и одноразовые скрипты в `app-sklad` могут изменять данные и требуют отдельной проверки параметров перед запуском.

## Локальные данные и резервирование

- Рабочая база по умолчанию находится в `app-sklad/sklad.db`. `SKLAD_DB` выбирает отдельную базу, `SKLAD_PORT` — порт, `SKLAD_CRED_FILE` — путь для файла с первичным паролем.
- Оригиналы вложений находятся в `app-sklad/files`. Экспорт DOCX хранится в папке `Заявки из приложения` в корне проекта. Для чистого запуска достаточно исходников и шаблонов. Для переноса действующего склада отдельно согласуйте передачу базы, вложений и документов.
- `backup.py` вызывает SQLite Backup API для штатной базы и копирует вложения в `C:\РАБОТА\Резервные копии\Склад ВЛ`. Эта утилита использует свои пути и не переключается через `SKLAD_DB`. Тестовый клон без `app-sklad/sklad.db` пропустит штатное резервирование. При ручном восстановлении остановите сервер и сначала сохраните текущую базу и вложения.
- `network.json` может включать прослушивание локальной сети и ограничение подсетью. Для разработки оставьте файл отсутствующим. Подключение к локальной сети настраивайте отдельно от запуска на новом ПК.

## Передача изменений через Git

Рабочая ветка — `app-sklad-vypiska`. Проверяйте `git status --short` и точный состав коммита. Ветка содержит интерфейс, сервер, генератор ТН и расписок и оба фирменных шаблона. Локальная конфигурация сети задаётся на конкретном компьютере.

Перед отправкой проверяйте состав файлов на наличие учётных данных, клиентских документов, SQLite, вложений и настроек конкретного рабочего компьютера. Базу, файл входа и рабочие вложения передавайте отдельно от исходников по согласованному каналу. Для разработки используйте синтетические данные.

Планы изменений лежат в `plans/`, результаты в `retros/`. Правила проекта описаны в `CLAUDE.md` и `rules/safety-workflow.md`.
