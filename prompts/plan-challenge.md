# Критика плана до написания кода

**Для чего:** найти дыры в плане, пока они ничего не стоят.
**Кому:** все, кто просит агента сделать функцию больше правки в одном файле.
**Что подставить:** `{{путь к плану}}`.

## Текст

```
Прочитай план {{путь к плану}} и не пиши код. Ответь по пунктам:

1. Критерии приёмки. Перечисли их и укажи, где в плане закрывается каждый. Что не закрыто?
2. Альтернативы. Назови 2–3 других способа решить задачу. Для каждого — плюсы, минусы, трудоёмкость.
   Почему выбранный лучше? Если не уверен — скажи.
3. Лишнее. Какие пункты плана не связаны с критериями? Предложи убрать или вынести в отдельные задачи.
4. Риски. Что может сломаться через неделю или месяц? Что будет при пустых данных, огромных данных,
   повторном нажатии, одновременных действиях?
5. Что нужно решить мне. Только настоящие развилки, по каждой — твой совет и причина.

Затем перепиши план целиком в улучшенном виде (не заплатками) и покажи. Реализацию не начинай.
```

## Пример результата

Переписанный план, где отмечено «убрано: рефакторинг модуля Z — отдельная задача» и добавлен тест на пустой ввод.
